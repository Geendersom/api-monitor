# Política de Segurança

## Versões suportadas

O projeto **API Monitor** está em desenvolvimento ativo. Correções de segurança serão aplicadas nas versões em manutenção conforme definido pelos mantenedores.

## Reporte responsável

Agradecemos a colaboração da comunidade para manter o projeto seguro.

Se você identificar uma vulnerabilidade de segurança:

1. **Não** abra uma Issue pública no GitHub.
2. **Não** divulgue detalhes da vulnerabilidade em fóruns, redes sociais ou outros canais públicos antes de uma correção ser disponibilizada.
3. Reporte o problema de forma privada e responsável.

## Como reportar

No momento, o canal dedicado de contato para reportes de segurança **ainda será definido** pelos mantenedores do projeto.

Até que um canal oficial seja publicado, utilize os meios privados disponibilizados pelos mantenedores do repositório no GitHub (por exemplo, contato direto via perfil do mantenedor, quando disponível).

Quando o canal oficial for definido, esta política será atualizada com as instruções definitivas.

## O que incluir no reporte

Para facilitar a investigação, inclua sempre que possível:

- Descrição clara da vulnerabilidade
- Passos para reproduzir o problema
- Impacto potencial (confidencialidade, integridade, disponibilidade)
- Versão ou commit afetado
- Evidências relevantes (sem expor dados sensíveis de terceiros)
- Sugestão de correção, se houver

## Processo de resposta

Após receber um reporte válido, os mantenedores buscarão:

1. Confirmar o recebimento do reporte
2. Investigar e validar a vulnerabilidade
3. Desenvolver e testar uma correção
4. Publicar a correção e, quando apropriado, creditar o reporte

O prazo de resposta pode variar conforme a complexidade e a gravidade do reporte.

## Divulgação coordenada

Pedimos que aguarde a correção antes de divulgar publicamente detalhes da vulnerabilidade. Isso ajuda a proteger os usuários do projeto.

## Escopo

Esta política se aplica ao código, configurações e documentação mantidos neste repositório.

Problemas de segurança em dependências de terceiros devem ser reportados aos mantenedores dos respectivos projetos, além de serem comunicados à equipe do API Monitor quando relevante para este repositório.
